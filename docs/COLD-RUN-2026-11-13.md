# Cold run #1 — the repeatability datum

**Date:** 2026-11-13. **Runbook:** `docs/RUNBOOK.md` (as written before the run).
**Target:** `VMAP.COM` (1991 DOS memory-map utility, original binary, 3,173 bytes,
SHA-256 `1ded169f…76a7`) — a binary referenced in **zero** pre-existing repo files, in a
format the lab had never mined (DOS `.COM`, 16-bit real mode).
**Executor:** a fresh-context agent with the identical blind brief (never exposed to the
repo's mechanism cards, transfer tests, or target findings).
**Branch:** `coldrun/vmap-m14` → merged to `main`. **Card:** M-14, status
`single-witness`.

## Why this run existed

`docs/PITCH-STRESS-TEST.md` recorded the failing point: *"'repeatable by any engineer'
is a belief, not a datum."* The runbook made it testable, and its graduation criterion
was explicit: **"the claim graduates to 'repeatable' only when run #1 completes and the
reviewer cannot tell which cards were written in-house."**

This file is run #1: what happened, what was independently verified, and whether the
claim graduates. **It does not.**

## What was produced

| artifact | path |
|---|---|
| probe contract (charter, written before evidence) | `targets/vmap/probe-contract.md` |
| notes — 15 constants, each with address + verbatim quote | `targets/vmap/notes-vmap.md` |
| mechanism card | `catalog/mechanisms/M-14-range-intersection-attribution.md` |
| transfer test | `catalog/transfer-tests/M-14-range-intersection-attribution/bench.mjs` |

**The mechanism (M-14, range-intersection attribution):** VMAP decides which memory block
"hooked" an interrupt vector by intersecting the Interrupt Vector Table's **segment
words** with the segment range of each block it already enumerated — a vector is
attributed to a block iff `block_start <= ivt_segment < next_block_start`. No per-block
hook registry exists, none is consulted, and no OS API is asked, because DOS exposes
none. The contract's pre-committed surprise target **held**.

## Independent audit (operator-verified, not agent-asserted)

The runbook makes the *verifier* a separate party whose job is to check that anchors
**support** the claim, not merely exist. Done against the original artifact:

1. **Bytes.** Decoded the claimed instructions directly from `VMAP.COM` at the claimed
   file offsets. At `0x0476` (flat `0x10576`): `8E C2` = MOV DX,ES · `8B 5E 04` = MOV
   BX,[BP+4] · `8B 56 06` = MOV DX,[BP+6] · `BF 02 00` = MOV DI,2 · `B9 00 01` = MOV
   CX,0x100 · `26 8B 05` = MOV AX,ES:[DI] · `83 C7 04` = ADD DI,4 · `3B C3` = CMP AX,BX ·
   `3B C2` = CMP AX,DX. **Every quoted instruction matches.** The format string
   `20 25 30 32 78 00` (" %02x\0") is at `0x0a49`; `"***** Memory Arena Trashed!"` at
   `0x09de`. The half-open range claim is exactly what the bytes say.
2. **Bench teeth.** Mutation-tested the load-bearing rule independently: closed lower
   bound, closed upper bound, swapped bounds, always-true, never-true — **5/5 mutants
   exit 1**; the probe-oracle mutant also exits 1. The bench has teeth.
   (Note for the record: the agent's own mutation claim reproduced correctly. A first
   audit attempt of mine *did not* reproduce it — the sed pattern used `&` in the
   replacement, which expands to the match, so the mutants were never applied. The
   "toothless bench" conclusion was mine, and it was wrong.)
3. **Contamination check.** The executor disclosed (D9) that its first read of
   `docs/LEARNINGS.md` used `limit: 60` and therefore returned lines 1–60, while §1 ends
   at line 22 — so it read part of §2 (Architectural findings, covering M-1…M-13).
   Checked: §2 contains **no** mention of IVT, interrupt vectors, attribution, hooks, TSRs,
   arenas, VMAP, or DOS memory maps. **The answer was not exposed.** The breach is
   recorded because it happened, not because it mattered.

## The verdict — the claim does NOT graduate

The executor's own answer to "would an engineer who had never seen this repo, given only
this runbook, have produced this card?" was **"Yes for the card; no for *this* card"**,
and the runbook's own criterion — *"the reviewer cannot tell which cards were written
in-house"* — was **not met**: the artifact carries a D1–D10 deviation log, an "Outcome"
section, and starts from a DOS utility rather than a game engine.

**Postscript (operator, after the run closed).** The graduation criterion above
was itself the wrong test, and it has been corrected. "The reviewer cannot tell
which cards were written in-house" measures provenance, not quality — run #1 is
the proof, since M-14 failed that bar (it carries a deviation log) while
passing every quality check, and provenance cannot detect a wrong card. The
criterion is now four authorship-agnostic checks (see `docs/RUNBOOK.md`
§First-run protocol). The verdict below stands: the *card* is good; the
*methodology* did not fully transfer, and the specific gaps are real. But the
question those gaps answer is "is the method transportable?", not "is the card
trustworthy?" — and the card's trustworthiness was settled directly, by decoding
the bytes and mutation-testing the bench.

 Two independent reasons,
both concrete:

- **The runbook would not have carried an engineer past two traps.** (a) `rea xrefs` on the
  flat string addresses returns **empty**, because the COM is loaded at PSP+0x100 so the
  code's operands are *segment-relative* and Ghidra's references live in segment space
  while the string inventory reports flat addresses — an engineer would conclude "the
  string is unreferenced" and stop. (b) Each `rea function` call re-imports the artifact
  into Ghidra (~25 s), there is no "dump all procedures" verb, and the harness kills
  background jobs when a tool call returns — so the obvious plan (decompile everything)
  is a trap that cost two crashed runs.
- **The bench shipped toothless and nothing in the runbook asked for a teeth check.**
  The first bench used a purely random fixture; because random handler segments almost
  never land on a block boundary, it **passed with the half-open rule broken**. Only
  explicit boundary vectors (24 of them) made the rule load-bearing.

The pitch line stays exactly as it was: *"compounding demonstrated internally"*, and
"repeatable by any engineer" stays labeled a **belief** — now with a datum attached and
ten enumerated fixes to pursue. That is a more useful belief than an untested one.

## The ten runbook gaps (now fixed in `docs/RUNBOOK.md`)

1. **Step 2 must state the address-space convention** — flat address ↔ segment-relative
   operand ↔ file offset, and that `rea xrefs` on flat addresses can be empty while the
   reference exists. *(The single most expensive trap.)*
2. **Budget in evidence produced, not tool invocations.** "≥ 25 tool invocations" is
   meaningless when each invocation re-imports the artifact.
3. **Require a mutation check on the bench:** "a bench that cannot fail is theater —
   mutate the load-bearing rule and show it fails."
4. **Replace "throughput ratio" with "the property the original mechanism claims"** —
   the example metrics push engineers toward wall-clock numbers the mechanism never
   claimed.
5. **Say what to do when a mechanism fits no existing family** (new family vs. nearest
   fit), and require the family list to be updated in the same commit.
6. **Make the contract's triage rule explicit:** a cheap, string-only triage *before* the
   contract is allowed and must be logged. "Before *any* evidence is collected" is not
   workable — picking a suspect behavior at all requires knowing what the program does.
7. **Require a "what the evidence refuted" line in the card**, even when the answer is
   "nothing" — it forces the surprise target to be settled rather than sidestepped.
8. **Require the contract to name the verifier and the address-space check** the verifier
   must perform.
9. **Add a "one open question" slot to the card format** — M-14 carries three genuine
   unresolved DOS-layout questions and had no home for them but prose.
10. **State that read-restrictions are the reader's to enforce and must be disclosed if
    overshot**, so a breach is reported rather than discovered later.

## Cost of the run

Three agent sessions (two harness interruptions, both caused by the sub-agent trying to
bulk-decompile 45 procedures through the CLI's per-call re-import — a trap the runbook
did not warn about), ~50 REA invocations, one day of human-equivalent budget. The card
is `single-witness`, not `proven`: a second witness is still required, and the
transfer test is a 2026-stack port, not a witness.

## What would make the claim graduate

Not a better card — a **fixed runbook and a second, independent target**. Concretely:
re-run this runbook against a different binary with the address-space rule, the
evidence-based budget, and the mutation check in place, and see whether the second run
produces a card with **no deviation log** — that is the actual test of "cannot tell which
cards were written in-house".
