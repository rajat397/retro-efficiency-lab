## Discussion summary

1. **Project thesis** (user): REA's open-source launch led a wave of people reverse
   engineering old, complex, hyper-efficient games/apps; community discussion observed
   that complex systems used to run in KB–MB budgets while modern apps are heavier.
   Hypothesis: rediscover and research the best techniques from old efficient software
   and apply them to modern contexts for impact.
2. **First plan reviewed and rejected** (from another agent): DX-Ball, 90s editor,
   Winamp-era player, Elite, DOS shmup — rejected as low mechanism density; techniques
   textbook or already re-invented.
3. **Rebuilt strategy** (this agent):
   - Selection principle: hard budget + public reconstruction + REA-fit + modern analogue.
   - Slate: Touhou TH04/TH05 → Doom → RCT → Another World / SCUMM / X-COM / KKrieger /
     console ROMs.
   - Mechanism families as extraction buckets (determinism, zero-alloc, data-as-program,
     procedural, streaming, format, lut).
   - Quality gates: single-witness → cataloged (≥2 witnesses) → proven (transfer test
     with numbers).
4. **User directive**: save every useful discussion, decision, and finding; create
   GitHub repo `rajat397/retro-efficiency-lab` and keep pushing.

## Session addendum 7 — FIRST TRANSFER TEST COMPLETE (M-2 → proven)

- Built `catalog/transfer-tests/M-2-slot-pool/` (bench.mjs + README): TH04's
  slot-pool mechanism vs the canonical JS push/sweep idiom, two scales
  (440/4096 slots), fairness contract documented.
- Results: allocations 247,977 → 0 (deterministic); peak heap 2.5-4.5x lower
  (12-20MB vs 4.4MB at modern scale); modern-scale timing 1.0-1.9x avg /
  1.1-2.8x p95 in pool's favor; at 1998 scale in V8 speed is a tie.
- Verdict: mechanism transfers; portable win = memory determinism, not raw
  speed at small scale. M-2 promoted to PROVEN.
- Test debugging surfaced 3 real pool invariants (each was a bug in our first
  pool): (1) the per-record age increment is load-bearing — losing it froze
  slot recycling; a fresh-written probe caught what patch-edited code hid;
  (2) single ownership-transfer point — double-push to the free stack
  corrupts it (death may only MARK a corpse; only REMOVE→FREE returns a
  slot); (3) RNG parity — both A/B sides must consume identical draws per
  attempt regardless of placement, else the comparison lies.
- Method note: the patch-archaeology bug (lost age line) reinforces the
  lab's evidence discipline — rebuilt-from-scratch probes are how we caught it.
- Commits: this session adds the transfer test, M-2 proven, M-3 cataloged
  (earlier), vision checkpoint.

## Session addendum 13 — TRANSFER TEST #4 complete (M-3 → proven)

- Built `catalog/transfer-tests/M-3-self-mutating-dispatch/`: 64-thread chain
  (AW's VM_NUM_THREADS), deferred (TH04/AW) vs inline (Doom-style transition
  actions) rebind application, two task iteration orders.
- Decisive numbers: inline = all 64 fire in 1 frame (fwd order) vs 64 frames
  (reverse order) — behavior implementation-defined, timelines diverge at
  frame 0. Deferred = 64 frames in BOTH orders, timelines identical —
  order-independent cascade.
- Honest cost: one-frame-per-link cascade latency (the TH04/AW tradeoff).
- Test bug caught: chain links must be ARMED for rebinds to land (matches
  AW's VM_INACTIVE_THREAD semantics); fixed and documented.
- M-3 promoted to PROVEN. Lab scoreboard: 3 proven (M-2, M-3, M-5), 4
