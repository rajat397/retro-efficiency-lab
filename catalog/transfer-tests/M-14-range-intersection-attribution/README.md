# M-14 transfer test — range-intersection attribution (no registry)

Run:

```
cd catalog/transfer-tests/M-14-range-intersection-attribution
node bench.mjs          # exits 0 on PASS, prints exactly one VERDICT: line
```

Node 22+. No dependencies beyond `node:crypto`, no network, no wall-clock in any metric.

## What it ports

`VMAP.COM`'s `FUN_1000_0570` (flat `0x10570`), verbatim:

```
ES = 0; DI = 2; CX = 0x100
AX = ES:[DI]; DI += 4
if (BX <= AX && AX < DX) -> attribute vector (0x100 - CX) to this block
```

`BX` = the block's own segment, `DX` = the next block's segment (exclusive bound) — the two
numbers the memory map already prints for that block. The dispatch table is the 256-entry table
of handler segments; the ranges come from the enumeration.

## What it measures

| strategy | what it is |
|---|---|
| **range-intersection** | the port above: derive ownership by intersecting the handler table with the enumerated ranges |
| **registry** | the obvious modern baseline: every hook registers itself at hook time |
| **probe** | ask each block which vectors it owns — requires an API DOS does not have; used as the oracle |

Ground truth is **physical containment** (which block holds the handler's code). The registry
answers a *different* question ("which module installed the hook"), so it disagrees exactly where
those two questions differ; the bench reports both numbers instead of picking a winner.

## The counters on the `VERDICT:` line

| counter | meaning |
|---|---|
| `rangeCorrect` / `rangeWrong` / `rangeUnattributed` | vectors correctly attributed / misattributed / whose handler lies in no enumerated range (BIOS/RT) |
| `rangeComparisons` | exactly `vectors × blocks` — the whole cost of the mechanism |
| `rangeWrites` / `rangeAllocations` | writes to state outside the caller's output buffer / heap allocations — both `0` |
| `registryCorrect` / `registryWrong` / `registryMissed` | the registry's answers to the *physical* question |
| `registryWrites` | registration records written at hook time |
| `probeCorrect` / `probeCalls` | the cooperative oracle |
| `digest` | SHA-256 over the canonical attribution table — pinned in the bench, so a third party can regenerate the fixture and confirm both measure the same thing |

## Reproducing the pinned digest

```
node bench.mjs --print-digest
```

The fixture is generated by a seeded integer-only PRNG (`mulberry32`, seed `0x5eed1e`), so the
digest is stable across machines and Node versions.

## The honest limits (also in the card's **Costs** field)

* The mechanism attributes by **address**, not by intent: a handler whose code lives in another
  module's range is reported against that range.
* The comparison is at **segment granularity** (64 KB in the original; a mapping in the port).
* The cost is `O(vectors × blocks)` — worse than a registry's `O(1)` lookup whenever every hook
  provably goes through one API. The mechanism pays off only when hooks can be installed
  out-of-band, which DOS guarantees and modern platforms do not.
* Handlers outside every enumerated range are attributed to nobody. The bench counts them
  (`rangeUnattributed`) rather than dropping them.
